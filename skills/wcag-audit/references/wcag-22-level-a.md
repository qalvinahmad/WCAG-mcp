# WCAG 2.2 Level A (summary)

This file documents common Level A success criteria and examples for auditing.

## Key criteria

- 1.1.1 Non-text Content — provide text alternatives for meaningful non-text content.
- 1.3.1 Info and Relationships — structure content semantically.
- 2.1.1 Keyboard — all functionality must be keyboard accessible.
- 2.1.2 No Keyboard Trap — users must be able to exit keyboard focus.
- 2.4.1 Bypass Blocks — navigation shortcuts should exist when needed.
- 2.4.2 Page Titled — each page should have a meaningful title.
- 3.1.1 Language of Page — page language should be programmatically determinable.
- 3.3.1 Error Identification — input errors must be identified.
- 4.1.2 Name, Role, Value — UI components should expose accessible metadata.
